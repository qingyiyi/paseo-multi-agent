# Paseo 多模型协作

保留原 Paseo Codex 对话与历史，由 GPT‑6.1 Terra 接收消息并分流。仅咨询设计、修改 Skill 或查看配置时，直接完成对应工作。遵循当前任务和项目已确认的权限与决策分工。

## 启动条件

- 确认当前主会话 ID、提供商和模型。主控为 `codex/gpt-6.1-terra`。需要切换时，引导用户在原对话的模型选择器切到 Terra，保留原线程。用当前主会话 ID 记录工作者归属和最终交付目标。
- 使用官方 Codex 和官方 Antigravity `agy acp`。**绝对禁止任何自建或第三方模型反代理、模型中转和消费订阅 API 转接。** 登录凭据由官方客户端管理，禁止提取、转发或写入交接材料。现有 Mihomo 仅提供网络出站路径。提供商、账号或模型不可用时，说明限制并交付可完成的部分，保留以上接入边界。
- 根据实际意图分为聊天与计划。用户明确要求的模型、交付范围和确认点优先。对外部提供商只发送用户授权范围内的必要材料。

## 聊天

普通对话、轻量问答、解释或措辞请求走聊天路线。Terra 向 `antigravity/gemini-4-hydrogen` 交接本条用户消息，以及理解必要指代所需的少量上下文。需要现场事实时，Terra 可先查证并交接最少的事实。由 Hydrogen 一次生成最终回复，以 `hydrogen:` 开头，经展示桥接写入原主对话。聊天省去计划、审核和执行阶段。

## 计划与执行

1. 对需要设计、拆分或实施方案的任务，Terra 整理简明任务单。默认请 `antigravity/gemini-4-neon` 起草。用户明确要求 Opus 5.5 时，先由 `antigravity/claude-opus-5-5` 起草，再由 Neon 阅读初稿并补充缺漏、风险或备选项。Neon 只返回有价值的增量，保留初稿可追溯。点名模型不可用时向用户说明。
2. 由 `codex/gpt-6.2-astra` 以 `high` 推理档核对目标、依赖、权限和验收，修订不足并补全可执行细节。先核实 `high` 已生效。对 Opus 路线，在统一计划中标注每项建议或实质改动的来源 `[Opus 5.5]`、`[Neon]`、`[Astra]`，合并项可有多个标签。Astra 按修订后任务单派发。用户只要求计划时，跳过实施并把审核后的计划作为交付定稿。用户指明待确认时，停在相应边界。
3. Astra 按需要分派代码实现、命令和测试给 `codex/gpt-6.2-sol`，将查证、图表日志核对和边界清楚的独立任务交给另一个 `codex/gpt-6.1-terra` 工作者。依赖任务顺序执行，独立任务可并行，避免多人写同一文件。两个工作者直接向 Astra 回报结果、证据位置与阻塞。
4. Astra 核实结果，汇总并写最终定稿。由 Astra 把定稿和必要写作要求交给 Hydrogen 一次润色。Hydrogen 保留结论、数字、公式、引用、不确定性和来源标签，经展示桥接把最终成稿写回 Terra 所在的原主对话。桥接正常交付时，Terra 只接收并记录必要进度。

## 复用与交付

- 同一原主会话按需复用一个 Sol、一个 Terra 子代理和一个 Neon。用明确的工作者 ID 和角色核对归属、模型、空闲状态。后续只传必要增量、路径和当前验收条件。Astra 在同一任务内持续审核、派发并汇总。相关任务可复用工作者，对无关任务保持短上下文。一条繁忙会话默认排队。复用本身不保证旧历史免计额度。
- **Hydrogen 实际生成的聊天回复或成稿首行固定为 `hydrogen:`**，第二行开始正文。原稿和状态消息使用自己的身份标识。展示桥接只把成稿写给用户。**Hydrogen 全文禁止自动回传给 Terra 或 Astra，禁止作为其后续模型上下文。**
- 自动写回需要已验证的 Paseo 展示桥接。桥接缺失或交付失败时，Terra 要在原主对话实际提供可用交付物或可打开的定稿链接，并说明 Hydrogen 回显状态。聊天用 Terra 的备用答复，计划或执行用 Astra 定稿。进度消息不能充当结果。只在用户明确接受独立 Gemini 会话交付时，才在该会话生成 Hydrogen 结果，并关闭完成回传。已成功生成的成稿用于恢复显示时，直接取回已有记录。
